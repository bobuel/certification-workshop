# Certification Launch

Read [launch method](../certification-workshop/references/method.md#launch) and [helpers](../certification-workshop/references/helpers.md). Assemble against the approved blueprint, source versions, accepted item revisions, enemy-group restrictions and required assessment methods. The helper proposes an exact form or reports infeasibility/search limits; never fill a gap with unreviewed items or quietly change weights.

Run check-form. Pin exact item revisions and content fingerprints and keep a release snapshot. Obtain approval target hashes from status: program approval covers policies/public guidance, blueprint approval covers the job model/sources, and form approval covers its assessment and release evidence. A hash identifies what was reviewed; it does not supply approval. Prepare candidate guidance, accessibility/accommodation process, registration/identity rules, permitted resources, retakes, appeals, scoring, result communication, renewal, support and incident procedures. Resolve owner policy decisions rather than filling them with arbitrary defaults.

Separate the public candidate guide from restricted exam material and keys. Use export audiences deliberately: candidate-guide contains only approved public program fields and domain titles; delivery is a restricted neutral JSON form, not a verified provider format. Map to a named provider only after reading that provider's current schema, validate an isolated import, and retain a readback/receipt before claiming publication. Reuse existing systems; no LMS, proctoring service or badge provider is required by this plugin.

Live readiness requires real evidence and program-owner release decisions; a synthetic demo can rehearse the complete flow without becoming a real release. Missing integrations yield reviewed files and an actionable handoff. Finish with release state, unresolved issues, destination and the next authorized action.
